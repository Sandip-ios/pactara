# iOS launch screen (needs a native rebuild)

These files make the native launch screen identical to the web one
(`src/components/SplashScreen.tsx`): white, "Pactara" wordmark centered,
200×54 pt, Inter 900 44px, letter-spacing −1.2px.

Copy into the Xcode project generated by `npx cap add ios`:

1. `LaunchScreen.storyboard` → replace `ios/App/App/Base.lproj/LaunchScreen.storyboard`.
2. `LaunchWordmark.imageset/` → copy the whole folder into
   `ios/App/App/Assets.xcassets/` (next to `AppIcon.appiconset`).
   The old `Splash.imageset` is no longer used and can be deleted.
3. `ios/App/App/Info.plist`, inside the top-level `<dict>`:

   ```xml
   <key>UIStatusBarStyle</key>
   <string>UIStatusBarStyleDarkContent</string>
   <key>UIUserInterfaceStyle</key>
   <string>Light</string>
   ```

   Dark status-bar icons during launch, and the app never switches to dark
   mode (it has no dark design).
4. `npx cap sync ios` (applies the new splash settings in `capacitor.config.ts`:
   white, no spinner, hidden by the app itself).
5. Build and run. iOS caches launch screens: delete the app from the phone
   (or restart it) before checking the new one.

Order: publish the web app first, then ship this native build. The new web
launch screen hides the native splash itself, so it works with the current
App Store build too (that one still shows its black splash until hidden). The
new native build stops hiding the splash on a timer and relies on the web app
to hide it, so it must not ship before the web publish.

# Shared-workout links open in the app (needs a native rebuild)

`https://pactara.lovable.app/w/<code>` links (and the existing `/join/<id>`
invite links) open straight in the app once this build ships. Until then they
open in Safari, where the page works signed in or out and saving still works.

The web side is already live with a web publish:
`https://pactara.lovable.app/.well-known/apple-app-site-association` lists
`/join/*` and `/w/*` for `44274JYF42.app.pactara`, served as
`application/json` with no redirect. The app already sends every opened link
(`appUrlOpen`, and the link that cold-launched it) to the right screen.

In Xcode:

1. Target **App** → **Signing & Capabilities** → **+ Capability** →
   **Associated Domains**, and add `applinks:pactara.lovable.app`.
   Same thing by hand: merge the `com.apple.developer.associated-domains`
   key from `App.entitlements` (in this folder) into
   `ios/App/App/App.entitlements`. Keep the keys already there
   (`aps-environment` for push); don't replace the file.
2. In the Apple Developer portal, the App ID `app.pactara` must have
   **Associated Domains** turned on (Xcode does this when automatic signing
   is on; with manual signing, regenerate the provisioning profile after).
3. Build and run. Check on a real iPhone: paste a `/w/<code>` link in Notes
   and tap it; it should open Pactara on the shared workout. iOS fetches the
   association file when the app is installed, so delete and reinstall the
   app if it still opens Safari.

Typing the link into Safari's address bar never opens the app (Apple's
rule); tapping it from Messages, Notes, Mail etc. does.

# Share your win: Instagram / Facebook Stories + Save to Photos (needs a native rebuild)

The Share your win screen (after a check-in) renders the check-in video with
the card on the phone. What works before and after this build:

| Button | Current App Store build (after web publish) | After this native build |
| --- | --- | --- |
| Instagram Stories | iPhone share sheet with the MP4 (Instagram is in it) | Opens Instagram Stories with the video as background and the card as a movable sticker |
| Facebook Stories | Same share sheet (Facebook is in it) | Opens Facebook Stories the same way |
| Save video | Share sheet; tap **Save Video** | Saves straight to Photos, toast "Saved to Photos" |
| More | Share sheet with the MP4 | Same |

If the Meta App ID isn't set yet, or Instagram/Facebook isn't installed, the
Stories buttons save the video to Photos, open the app and show "Saved to
Photos. Pick it in your story."

In Xcode:

1. Copy `PactaraShare/PactaraSharePlugin.swift` and
   `PactaraShare/MainViewController.swift` into `ios/App/App/` and add both to
   the **App** target (File → Add Files…, tick "App").
2. Open `ios/App/App/Base.lproj/Main.storyboard`, select the Bridge View
   Controller, and in the Identity inspector set **Class** to
   `MainViewController` (module: App). If the project already has its own
   `CAPBridgeViewController` subclass, don't add a second one: put the
   `bridge?.registerPluginInstance(PactaraSharePlugin())` line into its
   `capacitorDidLoad()`.
3. `ios/App/App/Info.plist`, inside the top-level `<dict>` (merge into an
   existing `LSApplicationQueriesSchemes` array if there is one):

   ```xml
   <key>FacebookAppID</key>
   <string>28899098959786133</string>
   <key>LSApplicationQueriesSchemes</key>
   <array>
     <string>instagram-stories</string>
     <string>facebook-stories</string>
     <string>instagram</string>
     <string>fb</string>
   </array>
   <key>NSPhotoLibraryAddUsageDescription</key>
   <string>Pactara saves your check-in videos to Photos when you tap Save video.</string>
   ```
4. Meta App ID `28899098959786133` is already set in `src/lib/meta-config.ts`
   (`META_APP_ID`) and in the Info.plist snippet above (`FacebookAppID`). The
   app sends it as `source_application` for Instagram Stories and as
   `com.facebook.sharedSticker.appID` (plus `source_application`) for Facebook
   Stories. It is public; the app secret is not used anywhere. In the Meta
   developer app, add the iOS platform with bundle ID `app.pactara`.
5. `npx cap sync ios`, build and run on a real iPhone with Instagram and
   Facebook installed: check in with a video → Share your win → Instagram
   Stories should open Instagram's story editor with the video and the card
   sticker; Save video should ask for Photos access once, then save.
