# Apple Health workout sync (needs a native rebuild)

Health sync is iPhone only. The app reads workouts, not steps, heart rate,
sleep, routes or other Health records. Nothing from Health counts as a
check-in until the member adds a video and taps Share. Only the posted
workout's source, UUID, type, start time, duration, distance and calories
are saved. Unposted workouts stay on the phone. Health areas are excluded
from analytics autocapture and masked for session recordings.

On José's Mac:

1. Download the latest project code and open Terminal in its folder.
   Run `npm install`, then `npx cap sync ios`, then `npx cap open ios`.
   The project already includes `@capgo/capacitor-health` 8.13.0, compatible
   with Capacitor 8. Keep the existing Capacitor configuration.
   `npx cap sync ios` must report 11 plugins (10 before the photo library picker), including
   `@capgo/capacitor-health`. If it reports 9, or the Health plugin is missing,
   then `includePlugins` in `capacitor.config.ts` does not list it: add
   `"@capgo/capacitor-health"` to that array and run `npx cap sync ios` again.
2. In Xcode, select the blue **App** project in the left sidebar, select
   the **App** target, then **Signing & Capabilities → + Capability → HealthKit**.
   Keep all existing capabilities. Do not enable Clinical Health Records
   or background delivery. If signing is manual, enable HealthKit on the
   App ID and regenerate its provisioning profile.
3. Open `ios/App/App/Info.plist` as source code. Inside the top-level
   `<dict>`, add this key (or update its existing value, never duplicate it):

   ```xml
   <key>NSHealthShareUsageDescription</key>
   <string>Pactara reads your workouts so you can check in with them and share their stats with your crew.</string>
   ```

   Do not add `NSHealthUpdateUsageDescription`: this version does not write
   workouts. Although the plugin can save individual health samples, its
   iOS workout API only supports querying workouts. There is no Save Pactara
   workouts to Health switch and no write permission request.
4. Build the **App** scheme and run on a real iPhone. On a new test account,
   make the first video check-in. The Health sheet should open over the
   celebration. Tap **Connect Apple Health** and allow **Workouts** only.
   Finish a Watch workout, or use an app that actually writes its workouts
   to Health. Strava/Nike Run Club must have their own Health sync enabled.
5. On the next day with no Pactara check-in, open Home. Tap **Use**, add a
   video, then Share. Check the crew post's activity, duration, distance,
   calories and source. Sync alone must not create a post or move a streak.
   US phone region uses miles, other regions use kilometres. Missing
   distance/calories are omitted, not filled with invented zeroes.
6. Open **Profile → Apple Health** (the new row below the plan section).
   Test the Show switch and **Open the Health app**. In Health, open
   **Profile → Apps → Pactara** to change read access. iOS deliberately
   does not reveal whether read access was denied: an empty result can
   mean no workouts or denial. Pactara never invents data or repeatedly
   asks for access. Older app builds without this plugin hide Health UI.
7. Before submitting the new App Store build, update **App Privacy** in
   App Store Connect: disclose the posted workout stats as **Health & Fitness**
   data linked to the member's account and used for **App Functionality**,
   not advertising, tracking or data brokerage. Update the privacy policy
   to explain the read-only workout permission, on-device unposted data,
   deliberate sharing with crews, stored posted fields, retention/deletion
   of posted check-ins and account deletion, permission revocation in Health,
   and that turning off Show stops reading but does not delete existing posts.
   Do not claim Pactara cannot read a workout after the member granted access.
   Review the label against every other app data use before submission.

This feature needs both your web publish and this native build. A web
publish alone cannot add the Health plugin to the current App Store app.

# iOS launch screen (needs a native rebuild)

These files make the native launch screen identical to the web one
(`src/components/SplashScreen.tsx`): white, "Pactara" wordmark centered,
200×54 pt, Inter 900 44px, letter-spacing −1.2px.

Copy into the Xcode project generated by `npx cap add ios`:

1. `LaunchScreen.storyboard` → replace `ios/App/App/Base.lproj/LaunchScreen.storyboard`.
2. `LaunchWordmark.imageset/` → copy the whole folder into
   `ios/App/App/Assets.xcassets/` (next to `AppIcon.appiconset`).
   The old `Splash.imageset` is no longer used and can be deleted.
3. `ios/App/App/Info.plist`, inside the top-level `<dict>`:

   ```xml
   <key>UIStatusBarStyle</key>
   <string>UIStatusBarStyleDarkContent</string>
   <key>UIUserInterfaceStyle</key>
   <string>Light</string>
   ```

   Dark status-bar icons during launch, and the app never switches to dark
   mode (it has no dark design).
4. `npx cap sync ios` (applies the new splash settings in `capacitor.config.ts`:
   white, no spinner, hidden by the app itself).
5. Build and run. iOS caches launch screens: delete the app from the phone
   (or restart it) before checking the new one.

Order: publish the web app first, then ship this native build. The new web
launch screen hides the native splash itself, so it works with the current
App Store build too (that one still shows its black splash until hidden). The
new native build stops hiding the splash on a timer and relies on the web app
to hide it, so it must not ship before the web publish.

# Shared-workout and shared-plan links open in the app (needs a native rebuild)

`https://pactara.lovable.app/w/<code>` and `/p/<plan>` links (and the
existing `/join/<id>` invite links) open straight in the app once this build
ships. The same Associated Domains capability covers all three; nothing
extra is needed for `/p/`. Until then they
open in Safari, where the page works signed in or out and saving still works.

The web side is already live with a web publish:
`https://pactara.lovable.app/.well-known/apple-app-site-association` lists
`/join/*`, `/w/*` and `/p/*` for `44274JYF42.app.pactara`, served as
`application/json` with no redirect. The app already sends every opened link
(`appUrlOpen`, and the link that cold-launched it) to the right screen.

In Xcode:

1. Target **App** → **Signing & Capabilities** → **+ Capability** →
   **Associated Domains**, and add `applinks:pactara.lovable.app`.
   Same thing by hand: merge the `com.apple.developer.associated-domains`
   key from `App.entitlements` (in this folder) into
   `ios/App/App/App.entitlements`. Keep the keys already there
   (`aps-environment` for push); don't replace the file.
2. In the Apple Developer portal, the App ID `app.pactara` must have
   **Associated Domains** turned on (Xcode does this when automatic signing
   is on; with manual signing, regenerate the provisioning profile after).
3. Build and run. Check on a real iPhone: paste a `/w/<code>` link in Notes
   and tap it; it should open Pactara on the shared workout. A `/p/<plan>`
   link should open that plan's page. iOS fetches the
   association file when the app is installed, so delete and reinstall the
   app if it still opens Safari.

Typing the link into Safari's address bar never opens the app (Apple's
rule); tapping it from Messages, Notes, Mail etc. does.

# Share your win: Instagram / Facebook Stories + Save to Photos (needs a native rebuild)

The Share your win screen (after a check-in, from your own feed posts and
from the Home Today card) renders the check-in video, or the photo on older
posts, with the card on the phone. What works before and after this build:

| Button | Current App Store build (after web publish) | After this native build |
| --- | --- | --- |
| Instagram Stories | iPhone share sheet with the MP4 / JPEG (Instagram is in it) | Opens Instagram Stories with the video (or photo) as background and the card as a movable sticker |
| Facebook Stories | Same share sheet (Facebook is in it) | Opens Facebook Stories the same way |
| Save video (Save image on photo posts) | Share sheet; tap **Save Video** / **Save Image** | Saves straight to Photos, toast "Saved to Photos" |
| More | Share sheet with the MP4 | Same |

If the Meta App ID isn't set yet, or Instagram/Facebook isn't installed, the
Stories buttons save the video to Photos, open the app and show "Saved to
Photos. Pick it in your story."

In Xcode:

1. Copy `PactaraShare/PactaraSharePlugin.swift` and
   `PactaraShare/MainViewController.swift` into `ios/App/App/` and add both to
   the **App** target (File → Add Files…, tick "App").
2. Open `ios/App/App/Base.lproj/Main.storyboard`, select the Bridge View
   Controller, and in the Identity inspector set **Class** to
   `MainViewController` (module: App). If the project already has its own
   `CAPBridgeViewController` subclass, don't add a second one: put the
   `bridge?.registerPluginInstance(PactaraSharePlugin())` line into its
   `capacitorDidLoad()`.
3. `ios/App/App/Info.plist`, inside the top-level `<dict>` (merge into an
   existing `LSApplicationQueriesSchemes` array if there is one):

   ```xml
   <key>FacebookAppID</key>
   <string>28899098959786133</string>
   <key>LSApplicationQueriesSchemes</key>
   <array>
     <string>instagram-stories</string>
     <string>facebook-stories</string>
     <string>instagram</string>
     <string>fb</string>
   </array>
   <key>NSPhotoLibraryAddUsageDescription</key>
   <string>Pactara saves your check-in videos and photos to Photos when you tap Save.</string>
   ```
4. Meta App ID `28899098959786133` is already set in `src/lib/meta-config.ts`
   (`META_APP_ID`) and in the Info.plist snippet above (`FacebookAppID`). The
   app sends it as `source_application` for Instagram Stories and as
   `com.facebook.sharedSticker.appID` (plus `source_application`) for Facebook
   Stories. It is public; the app secret is not used anywhere. In the Meta
   developer app, add the iOS platform with bundle ID `app.pactara`.
5. `npx cap sync ios`, build and run on a real iPhone with Instagram and
   Facebook installed: check in with a video → Share your win → Instagram
   Stories should open Instagram's story editor with the video and the card
   sticker; Save video should ask for Photos access once, then save.

# Rich check-in notifications (needs a native rebuild)

When someone in a crew checks in, the push shows their profile photo as the
big icon (with a small Pactara badge in the corner) and a thumbnail of their
video (or photo) on the right, like Instagram or WhatsApp. The server side is
already live with a web publish. Until this build ships, phones keep showing
the plain Pactara icon; nothing breaks.

Files in this folder: `NotificationService/NotificationService.swift` and
`NotificationService/Info.plist`.

In Xcode (open `ios/App/App.xcworkspace`):

1. **Add the extension.** Menu **File → New → Target…** → pick
   **Notification Service Extension** → **Next**.
   - Product Name: `NotificationService`
   - Team: the same team as the App target
   - Language: Swift
   - Embed in Application: **App**
   - Click **Finish**. If Xcode asks "Activate NotificationService scheme?",
     click **Don't Activate** (you keep building the App scheme).
   - Select the new **NotificationService** target → **General** →
     **Minimum Deployments**: set the same iOS version as the App target.
     (Xcode picks the newest iOS by default; if it's higher than the phone's
     iOS, the extension silently never runs.)
2. **Use our files.** In the left sidebar, open the new `NotificationService`
   folder. Replace the contents of its `NotificationService.swift` and
   `Info.plist` with the two files from this folder (open ours, select all,
   copy, paste over Xcode's). Keep the file names and locations Xcode made.
3. **Main app capability.** Select the **App** target → **Signing &
   Capabilities** → **+ Capability** → **Communication Notifications**.
   Keep **Push Notifications** (and everything else already there).
4. **Main app Info.plist.** Open `ios/App/App/Info.plist` and add, inside the
   top-level `<dict>`:

   ```xml
   <key>NSUserActivityTypes</key>
   <array>
     <string>INSendMessageIntent</string>
   </array>
   ```

   If `NSUserActivityTypes` already exists, add the `<string>` line to it
   instead of a second key.
5. **Signing for the extension.** Select the **NotificationService** target →
   **Signing & Capabilities** → tick **Automatically manage signing** and pick
   the same team. Xcode creates its App ID (`app.pactara.NotificationService`)
   and provisioning profile for you. No Firebase or other library is needed
   in the extension.
6. **Test on a real iPhone** (the simulator doesn't get real pushes). Build
   and run the **App** scheme on your phone, allow notifications, lock the
   phone, and have someone in your crew check in with a video. The
   notification should show their photo as the big icon with the small
   Pactara badge, and the video thumbnail on the right. On a check-in with
   no photo or video you get their photo icon without a thumbnail.
7. **If it still shows the plain Pactara icon:**
   - Check the **App** target has **Communication Notifications** under
     Signing & Capabilities (step 3). If it does and it still fails, add the
     same capability to the **NotificationService** target too.
   - Check `NSUserActivityTypes` with `INSendMessageIntent` is in the
     **App** target's `Info.plist` (step 4), not only in the extension's.
   - Check the extension's Minimum Deployments is not higher than the phone's
     iOS (step 1). The photo-style icon needs iOS 15 or later; on older iOS
     you still get the thumbnail.
   - Check the push itself has `"mutable-content": 1` inside `aps`. Every
     check-in push from the server includes it (ask for the server log if in
     doubt). Without it, iOS never runs the extension and shows the plain
     icon.
   - Delete the app from the phone, build and run again (iOS sometimes keeps
     the old notification setup).
   - In **Settings → Notifications → Pactara**, make sure notifications are
     allowed and not set to "Deliver Quietly" or summary only.

# Photo library posts (needs a native rebuild)

New posts from the camera roll use `@capawesome/capacitor-file-picker`.

1. `npx cap sync ios` must report 11 plugins, including
   `@capawesome/capacitor-file-picker` and `@capgo/capacitor-health`.
2. In `ios/App/App/Info.plist`, add (keep existing keys):
   ```xml
   <key>NSPhotoLibraryUsageDescription</key>
   <string>Pactara opens your library so you can post photos and videos.</string>
   <key>NSCameraUsageDescription</key>
   <string>Pactara uses the camera for check-ins and new posts.</string>
   <key>NSMicrophoneUsageDescription</key>
   <string>Pactara records sound with your videos.</string>
   ```
   The camera and microphone keys likely exist already for check-ins.
3. Until this build ships, older App Store builds fall back to the system
   file picker, which also offers the photo library and camera.
